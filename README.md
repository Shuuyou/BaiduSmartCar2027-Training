# HDU 智能车百度创意组 · 2027 届培养仓库

面向新大二、大一年级成员的选拔与培养仓库。培养方式为**自学路线 + 里程碑验收**：学习由你自主完成，路线图、自动评测与集中验收由组别提供。

## 关于本组别

- 参赛项目：全国大学生智能汽车竞赛 · 百度创意组；
- 技术核心：飞桨深度学习（目标检测/OCR）、文心大模型应用、Linux 工程环境、任务调度算法；
- 比赛用车模为组委会官方指定设备，赛前统一采购。**培养期全程不使用真机**，所有训练任务在个人电脑与免费云算力上完成。

## 如何使用本仓库

1. Fork 本仓库到自己的账号（建议同时将 fork 设为 Private）；
2. 按分支顺序完成任务：切到对应任务分支，README 即任务书；
3. 所有学习记录、踩坑笔记与任务产出提交在自己的 fork 中——**提交轨迹是考核证据的一部分**；
4. push 后 Actions 自动校验产出结构，校验结果见仓库 Actions 页签。

> **首次 fork 后必看**：GitHub 默认禁用 fork 仓库的 Actions。请进入自己仓库的 `Actions` 页签，点击绿色按钮 `I understand my workflows, go ahead and enable them` 启用，否则 push 后不会自动判题。

## 培养路线

| 阶段 | 时间 | 内容 | 验收 |
|---|---|---|---|
| M0 | 10–11 月 | 工具生存：Linux / Python / Git / 飞桨环境；任务零、一、二 | 自动校验 + 集中验收日 |
| M1 | 12–1 月 | 分流项目：感知线（训练检测模型）或算法线（循迹仿真） | 项目答辩 |
| M2 | 1–2 月 | 小组软件闭环：检测 + 车道识别 + 仿真控制 + 任务状态机 | 集中演示 + 互评 |
| M3 | 3–4 月 | 综合评分、规则精读、技术方案文档，确定队伍名单 | 书面 + 答辩 |
| M4 | 赛前 | 真机集中学习与联调（车模到位后） | 实车验收 |

## 基本规则

1. **鼓励使用 AI 工具**。考核的对象是驾驭 AI 的工程判断力：验收时需能说明每一步的依据、报错的定位过程。无法解释自己提交内容的，判定不通过。
2. **过程记录与产出同等重要**。`notes.md` 中记录报错原文、尝试与结论；小步迭代的提交历史优于一次性大提交。
3. **允许申请一次延期**（上限两周，须提前说明）。连续两周无提交且未说明原因者，视为退出本轮培养。

评分构成、追问清单与分层机制详见 `docs/考核规则.md`。
