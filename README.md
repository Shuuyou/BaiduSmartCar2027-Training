# 任务一：让一张图片被 AI 看懂

> 定位：M0 核心任务 · 2–3 周 · 零硬件 · 直通赛道主技术栈（目标检测）
> 你是一辆智慧农场小车的感知工程师。第一步：让小车"看懂"一张农场照片。

## 任务要求

1. 在 Ubuntu（双系统或 WSL2 均可）里安装 PaddlePaddle 与 PaddleDetection；
2. 用**官方预训练模型**对 `data/` 里的 **5 张图片**做目标检测（图片自选，建议农业/道路场景；组织方也可能在群里发布指定图）；
3. 输出带检测框的可视化结果到 `output/`（5 张，命名 `vis_1.jpg` … `vis_5.jpg`）；
4. 把每张图检测到的目标类别和数量整理成 `results.json`（格式见 `results.example.json`）；
5. 全程记录在 `notes.md`：每个报错原文 + 你做了什么 + 结果；
6. push 到你 fork 的仓库——**Actions 会自动校验** results.json 格式、output/ 图片数量、notes.md 是否为空。

## 可以用任何 AI 工具，但是

验收时你要能回答"AI 给你的每一步你都做了什么"。

### 验收追问清单（提前公开，照着自己练）

- 这个安装命令是干什么的？pip 和 conda 有什么区别，你为什么用这个？
- 你遇到的最大报错是什么？报错原文是什么？你怎么定位的？
- 检测结果里的置信度阈值是什么？调高/调低会怎样？
- 如果让你把检测类别换成"水果"（模型没见过），你会怎么做？

## 提交结构

```
├── data/            # 你选的 5 张输入图片
├── output/          # 5 张可视化结果 vis_1.jpg ... vis_5.jpg
├── results.json     # 结构化检测结果
├── notes.md         # 踩坑记录（必填，空文件=不过）
└── (你的代码/脚本)
```

## 评分

自动分 60%（Actions 校验 + OJ 热身题）+ 验收日 40%（现场跑 + 追问 + 修一个预埋故障，10 分钟内修好=满分）。

预期完成率约 50–60%，这是正常比例。两周后仓库还是空的，我们会找你聊一次。

## 用 AI 的正确姿势（本任务）

- ✅ 让 AI 解释 CUDA/依赖报错、比较安装方案、解释检测结果含义
- ❌ 让 AI 直接生成"整个工程"然后跑不通就换一个 prompt 再要——跑不通时你没有任何排查手段
- 卡住时先做这三件事：读报错原文 → 搜/问 AI 报错关键行 → 把你的完整操作步骤和报错贴给 AI
